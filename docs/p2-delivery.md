# P2 交付说明

最后更新：2026-09-01

## 运行时与回放

- 每局状态包含 `seed`、`rngState`、`ruleVersion`、`actionLog`、独立递增的 `nextActionId` 和 `replayCheckpoints`；检查点同时携带稳定状态摘要和轻量状态帧。状态帧只保存观赛必要字段：角色位置/朝向/生命/装备/背包/淘汰状态、区域开放状态、资源、关系、剧情线索和热度，不保存对话、提示词、API 密钥或第二份完整世界。
- 服务端规则随机数统一经持久化 LCG 产生；相同 seed 会得到相同随机序列。
- `actionLog` 记录模型动作、规则 AI 实际动作、结构化目标、校验结果和回退原因；每条被接受的动作携带紧凑状态补丁，周期规则、主办方干预与小游戏结算也使用同一格式。无可见状态变化的周期帧不会占用日志容量。日志不包含提示词、响应原文或 API 密钥。
- `replayRecordedAction()` 和 `replayRecordedActions()` 复用生产动作执行层，按 `ts`、`id` 重演已接受的结构化行动；它们不申请驾驶权、不计入模型额度，也不调用 DeepSeek。规则 AI 的搜索、攻击、撤离、移动、治疗、购买和结盟均通过同一动作执行层。
- 前端回放从时间点之前最近的检查点开始，按 `actionId` 应用后续状态补丁。Pixi、直播 HUD、区域封锁、角色详情、关系、资源、剧情与决策审计均读取同一回放帧；进入回放会停止云端决策调度。旧局没有状态补丁时仍可从已有检查点查看。
- DeepSeek 密钥只由 Convex Action 从云变量 `DEEPSEEK_API_KEY` 读取。浏览器只请求调度，不传递或缓存密钥；Action 只提交受限的结构化行动与脱敏失败原因。
- 关系运行时还包括重逢、危局守护和绝境逆转；这些事件各自使用一次性剧情标记并写入中文播报。
- 物品运行时包括高影响物品的稀有度和交易价值、加权掉落、区域资源枯竭/刷新，以及医院、市场、格斗笼的区域 buff。
- 区域剧情中的笼门封锁是可验证的持续状态：锁定会拒绝区域内 AI 的移动，战略总览显示倒计时，主办方的“拆除笼门”会清除锁定。信息贩子与林中低语也会分别消耗物资、授予线索和延长安全区停留时间。
- 角色运动采用独立的高频 locomotion 层：到达区域导航点后继续规划下一段 A* 路径，不消耗 DeepSeek 额度；12 秒战术层仍决定攻击、搜索、跨区、结盟和交易。谈判会短暂停步，`speech` 经服务端清洗后进入 `dialogueLog`，由地图气泡、公屏和角色详情共同呈现。
- locomotion 层保存最近真实位移时间；碰撞等待超过 1.8 秒或移动路径超过 2.8 秒没有坐标进展时，服务端会清理失效路径、跳过拥挤导航点并立即重新寻路，避免角色因残留 `pathfinding` 状态长期站立。
- 战斗角色的 A* 碰撞不再读取旧 AI Town `objectTiles`：那份墙体与当前 13 区战场原画并不对应，并会形成不可见孤岛。战斗层保留地图边界、存活角色动态碰撞，以及 `battleArena.ts` 对目的地、区域和地标的校验；已淘汰角色不会继续堵住路线。
- AI 的完整交谈文字只进入直播对话框和角色交谈记录；地图上的角色头顶仅保留省略号状态标记。对话框按提议、回应的顺序展示双方头像、姓名和台词，9 秒后自动退出，不占用关键播报区域。
- 前端不再直接把规则层的 `MOVE` 当作移动证据：只有序列化速度大于 0 才显示移动标记，路线计算和碰撞避让不会冒充移动。自动导播将近期关键事件包装为“交火现场、淘汰瞬间、区域剧情”等直播镜头，平静时在热点选手间定时巡场。
- 跟随镜头读取与角色渲染相同的历史位置样本，并使用逐帧指数阻尼追踪；相同时间跨度在不同刷新率下保持一致的收敛轨迹，自动导播切换角色时也不再硬跳。
- 区域剧情使用 `storyLog` 保存跑团式过程，包括场景、角色选择、检定名称、D20 骰点、属性加值、难度、成败和后果。永久禁区及临时剧情封锁均直接渲染到 Pixi 战场；直播顶部只保留高优先级事件，避免连续搜索、移动和决策日志遮挡战斗。

## 视觉资产

- `public/assets/battle/arena-live-map.png`：使用参考仓库纯地图的 13 区俯视战场视觉层，与战略总览保持一致。
- `public/assets/battle/contestant-portraits.png`：12 名原创参赛者识别图集，用于直播焦点、角色档案、对话框和战略总览。
- `public/assets/battle/contestant-sprites-v1.png`：12 名原创参赛者的 4×3 透明俯视角全身图集，保持头像身份顺序；Pixi 按角色 ID 切片，并渲染移动起伏、左右朝向、选中环、生命条和淘汰态。
- `public/assets/battle/area-landmarks-v1.png`：A01-A12、S01 的 4×4 透明地标图集，依次对应堡垒、演播塔、书库、格斗笼、学园、医院、训练场、市场、武器库、密林、法庭、观测站与真相之间。
- `public/assets/reference/ui/`：接入参考仓库的事件图标、生命电池和按钮状态资源；来源及授权注意事项见 [美术资产来源与接入记录](./asset-provenance.md)。
- 所有区域 ID、锚点、邻接、出生点、区域多边形、导航节点和地标碰撞都由 `data/battleRoyaleConfig.ts` 与 `data/battleArena.ts` 统一定义；跨区落点及 AI 搜索游走从同一份可走导航节点取点。
- Pixi 区域锚点是可点击直播地标：点击后锁定区域镜头并显示危险、开放/剧情封锁、存活人数、资源余量、机制与 Buff；总览的区域跟拍按钮调用同一入口。

## P2 验收清单

- 直播模式不被总览覆盖，用户可锁定 AI 或恢复自动导播。
- 新开局仅经 `world.resetBattle` 执行一次，并重置状态为 12 名唯一角色。
- 同 seed 的 RNG 以及固定模型动作日志的批量重演夹具稳定通过；夹具同时验证排序、拒绝日志过滤、不消耗模型额度，以及搜索掉落、资源扣除与局部寻路状态的一致性。
- 最终内容仍需补齐：逐瓦片完整寻路网格，以及参考配表中逐条剧情的全部文案与后果。物品稀有度、检查点后动作补丁、固定回放夹具和规则动作共享执行层已纳入运行时与自动测试。
