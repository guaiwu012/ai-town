# P2 交付说明

最后更新：2026-08-07

## 运行时与回放

- 每局状态包含 `seed`、`rngState`、`ruleVersion`、`actionLog`、独立递增的 `nextActionId` 和 `replayCheckpoints`；检查点同时携带稳定状态摘要和轻量状态帧。状态帧只保存观赛必要字段：角色位置/朝向/生命/装备/背包/淘汰状态、区域开放状态、资源、关系、剧情线索和热度，不保存对话、提示词、API 密钥或第二份完整世界。
- 服务端规则随机数统一经持久化 LCG 产生；相同 seed 会得到相同随机序列。
- `actionLog` 记录模型动作、结构化目标角色/区域、校验结果及规则 AI 回退原因；日志不包含提示词、响应原文或 API 密钥。
- `replayRecordedAction()` 和 `replayRecordedActions()` 复用生产动作执行层，按 `ts`、`id` 重演已接受的模型结构化行动；它们不申请驾驶权、不计入模型额度，也不调用 DeepSeek。规则 AI 同时写入实际的搜索、攻击、撤离、移动、治疗、购买或结盟动作，并保留回退原因；尚未把每一条规则路径都承诺为可独立重演的完整状态还原器。
- 前端回放控件显示行动、检查点和关键事件；进入回放会停止云端决策调度，绝不触发模型调用。实时缓冲可逐帧回看，跳到持久化检查点时 Pixi 会恢复当时的角色位置与战斗状态；旧局没有状态帧时自动退化到实时缓冲。
- DeepSeek 密钥只由 Convex Action 从云变量 `DEEPSEEK_API_KEY` 读取。浏览器只请求调度，不传递或缓存密钥；Action 只提交受限的结构化行动与脱敏失败原因。
- 关系运行时还包括重逢、危局守护和绝境逆转；这些事件各自使用一次性剧情标记并写入中文播报。
- 物品运行时包括高影响物品的稀有度和交易价值、加权掉落、区域资源枯竭/刷新，以及医院、市场、格斗笼的区域 buff。
- 区域剧情中的笼门封锁是可验证的持续状态：锁定会拒绝区域内 AI 的移动，战略总览显示倒计时，主办方的“拆除笼门”会清除锁定。信息贩子与林中低语也会分别消耗物资、授予线索和延长安全区停留时间。
- 角色运动采用独立的高频 locomotion 层：到达区域导航点后继续规划下一段 A* 路径，不消耗 DeepSeek 额度；12 秒战术层仍决定攻击、搜索、跨区、结盟和交易。谈判会短暂停步，`speech` 经服务端清洗后进入 `dialogueLog`，由地图气泡、公屏和角色详情共同呈现。
- 区域剧情使用 `storyLog` 保存跑团式过程，包括场景、角色选择、检定名称、D20 骰点、属性加值、难度、成败和后果。永久禁区及临时剧情封锁均直接渲染到 Pixi 战场；直播顶部只保留高优先级事件，避免连续搜索、移动和决策日志遮挡战斗。

## 视觉资产

- `public/assets/battle/arena-live-map.png`：使用参考仓库纯地图的 13 区俯视战场视觉层，与战略总览保持一致。
- `public/assets/battle/contestant-portraits.png`：12 名原创参赛者识别图集，用于直播焦点、角色档案和场内头顶识别徽记。
- `public/assets/reference/ui/`：接入参考仓库的事件图标、生命电池和按钮状态资源；来源及授权注意事项见 [美术资产来源与接入记录](./asset-provenance.md)。
- 所有区域 ID、锚点、邻接、出生点、区域多边形、导航节点和地标碰撞都由 `data/battleRoyaleConfig.ts` 与 `data/battleArena.ts` 统一定义；跨区落点及 AI 搜索游走从同一份可走导航节点取点。

## P2 验收清单

- 直播模式不被总览覆盖，用户可锁定 AI 或恢复自动导播。
- 新开局仅经 `world.resetBattle` 执行一次，并重置状态为 12 名唯一角色。
- 同 seed 的 RNG 以及固定模型动作日志的批量重演夹具稳定通过；夹具同时验证排序、拒绝日志过滤、不消耗模型额度，以及搜索掉落、资源扣除与局部寻路状态的一致性。
- 最终版本需补齐：逐瓦片完整寻路网格、逐条剧情分支与“检查点后的每一条规则行动”完整状态还原器。物品稀有度、持久化状态帧与固定回放夹具已纳入运行时和测试。
